riggs1890-lexgym · cookbook 01 · built with Tinker

Teach a model one dictionary, and keep its habit of looking things up

Supervised fine-tuning of Inkling 2 Small on Stephen R. Riggs, A Dakota-English Dictionary (1890). Three passes over 69,461 rows took recall from 3% to 84%. Use of the dictionary lookup tool stayed at 100%.

How to read this. Recall keeps rising with each pass, because recall is memory of the book. The held-out scores are flat after pass 1, because those tasks use word families the model never saw and depend on rules, which the model learns quickly.

The base model already called the tool correctly. Its lookup errors were answers in its own words. Training moved the lookup score to 1.000 by teaching it to give the entry text as written. The important fact is the comparison: on the earlier Qwen runs, the same kind of training removed tool use almost completely.

Two things differ between the Inkling run and the Qwen runs: the model and the training file. This run does not show which one protects tool use. A Qwen run on the mixed file is the control that would answer this.

Step 1Turn the dictionary into tasks

The source is a public-domain scan. Each entry was parsed into a headword, syllable division, part of speech, definition, listed forms, and the word it is derived from. From these fields the task builder makes eight task types and one lookup index.

The split is by word family. One family in ten is held out with all its derived words. A model cannot pass a held-out task because it saw a close relative of the word in training. Recall tasks are different by design: they ask about words that were in training, so they measure memory.

The tasks are on the Hub at HarleyCooper/riggs1890-lexicon-graph.

Step 2Add solved lookup conversations to the training file

The first training file had 56,120 rows, and each row was one question and one answer. Training on it taught the model to answer at once in every case. After one pass, Qwen3.5-4B made zero lookup calls and its lookup score fell from 0.727 to 0.013.

The fix is to put the tool in the training data. build_mixed_sft.py writes each lookup task as a solved conversation. No teacher model is necessary, because the lookup index already holds the entry text and the gold answer:

system     You can read the dictionary. To read the entry for a Dakota word,
           reply with exactly one line: 'LOOKUP: <word>'. ... You have 3 lookups.
user       Read the dictionary. The Dakota word aska is derived from another word.
           What is the English definition of that other word?
assistant  LOOKUP: aska
user       ENTRY: a-ska', v. n., to become white on [derived from: ska]
assistant  LOOKUP: ska
user       ENTRY: ska', adj., white; clear, as, mini ska, clear water: clean, new ...
assistant  ANSWER: white; clear, as, mini ska, clear water: clean, new ...

Each conversation is replayed against the rules of the evaluation environment and kept only if it scores 1.0. Then it is written as one row for each assistant turn, so the loss is always on the last assistant message of a row. This gives each turn the same token prefix in training that the model sees when it generates.

The result is 69,461 rows: 56,120 word rows and 13,341 lookup rows (3,000 one-hop conversations and all 2,447 two-hop conversations). About one row in five shows the tool.

Step 3Train on Tinker

Tinker runs the model. Your code runs on any small CPU machine and sends batches to the service. This run used a free-tier Hugging Face Job as that machine.

python launch_sft_curve_job.py --model-name thinkingmachines/Inkling-2-Small

The job does four things in order: it evaluates the base model, trains LoRA for three passes with a checkpoint at the end of each pass, evaluates each checkpoint, and uploads traces and results.

Reasoning off for Inkling

Qwen has a renderer with no thinking block. Inkling has one renderer and a reasoning effort value in a system message. The job sets the default effort to 0 before training and evaluation, so the two use the same prompt:

TML=$(python -c "import importlib.util as u; \
  print(u.find_spec('tinker_cookbook.renderers.tml_v0').origin)")
sed -i 's/^DEFAULT_EFFORT: float = 0.9$/DEFAULT_EFFORT: float = 0.0/' "$TML"

A rendered training row then looks like this:

<|message_system|>You answer from Stephen R. Riggs, A Dakota-English Dictionary (1890). ...
<|message_system|>Thinking effort level: 0
<|message_user|>Give the English definition of the Dakota word: pazezeya
<|message_model|>ANSWER: swinging
Effort 0 does not fully stop reasoning in the base model. In the base evaluation some answers still opened a thinking block, and the base model sampled 1.27 million tokens on 1,500 tasks. The tuned model sampled 23,000 tokens on the same tasks, with no answer longer than 58 tokens.

Step 4Evaluate each checkpoint

The evaluation set is 1,500 tasks: 150 held-out tasks for each of six types, and 600 recall tasks. Temperature is 0. The score is exact match after the normalisation in lexgym/scoring.py, and the lookup tasks also record how many calls the model made and whether it read the target entry.

The answer limit in the repository is 96 tokens. This run raised it to 2,048 so that a base model that still reasons is not cut off before its answer.

Step 5Sample from the checkpoint

Each saved sampler checkpoint can be called through Tinker's OpenAI-compatible endpoint. This call was tested against the pass 3 checkpoint and returned the correct entry text:

from openai import OpenAI
import os

client = OpenAI(
    base_url="https://tinker.thinkingmachines.dev/services/tinker-prod/oai/api/v1",
    api_key=os.environ["TINKER_API_KEY"],
)
out = client.chat.completions.create(
    model="tinker://551aa04a-f385-5fdc-825c-7f47cf3a769d:train:0/sampler_weights/final",
    messages=[
        {"role": "system", "content": "You answer from Stephen R. Riggs, A Dakota-English "
         "Dictionary (1890). Use the spelling of that book. Give only the answer on one "
         "line, starting with 'ANSWER:'."},
        {"role": "user", "content": "Give the English definition of the Dakota word: iwiśtaŋ"},
    ],
    max_tokens=128, temperature=0.0,
)
print(out.choices[0].message.content)   # ANSWER: to treat well, as a sick person

The endpoint is in beta. Checkpoints on this account expire seven days after they are made, so a checkpoint to keep must be downloaded or pushed to the Hub with the tinker checkpoint commands.

What did not workThree earlier attempts

  • Word rows only. Qwen3.5-4B and Qwen3.6-35B reached 0.392 and 0.528 recall after three passes, and both lost the tool. Lookup scores fell to 0.02 and 0.03.
  • Reinforcement learning with reasoning on. A 30-step test on Inkling with a 25,000-token limit cost $13.13 and showed no learning. Episodes used 1,400 to 3,900 reasoning tokens each, and a full pass over the tasks was priced at about $4,000.
  • One row for a whole conversation. Training on all assistant messages of a multi-turn row is wrong for a renderer that does not keep the same token prefix between turns. One row for each assistant turn removes the problem for every renderer.

A short reinforcement learning pilot from a trained checkpoint did work on Qwen3.5-4B: 30 steps for $1.12 brought the one-hop lookup score from 0.00 back to 0.85. The mixed file gets the same effect inside supervised training, at no added cost.

LimitsWhat this result does not show

  • Recall measures memory of words that were in training. It is the correct test for "does the model know this book", and it says nothing about new words.
  • The score is exact match against one book in its 1890 spelling. The book has errors and the views of its time. A correct score means agreement with Riggs, and Dakota speakers are the authority on the language.
  • The model never chooses between memory and the tool. The task name decides if the tool is available. A test where the model must decide is the next experiment.
  • Every number is from one run with one seed.

Use it for a different languageThe recipe in five lines

  1. Parse a dictionary into entries with a headword, a definition, and any cross-references.
  2. Write word tasks and lookup tasks from the entries, and hold out one word family in ten.
  3. Build solved lookup conversations from the index and add them to the word rows, one row for each assistant turn.
  4. Train LoRA for three passes and save a checkpoint after each pass.
  5. Score each checkpoint on recall, held-out rules, and tool use, and read the three curves together.
